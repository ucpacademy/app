# Project Guide

## Overview
This project is a multilingual education marketplace website with two main areas:
- Public catalog pages for students and visitors
- Authenticated dashboard sections for admin and student users

The app uses Next.js App Router and a route structure based on `src/app/[lang]`.

---

## Data Architecture & Entity Relationships

The platform's data is structured like a funnel, starting from broad academic concepts down to individual student progress.

### 1. The Academic Catalog (The "What")
This represents the theoretical structure of education on the platform, independent of specific schools or teachers.
- **`majors`**: The highest level, representing a broad field of study (e.g., Engineering, Medicine, Business).
- **`branches`**: A specific specialization inside a major.
  - *Connection*: Every branch belongs to exactly **one** Major. (e.g., *Software Engineering* inside the *Engineering* major).

### 2. The Learning Path (The "How" & "Where")
This is where theoretical branches become real, enrollable offerings created by Teachers or Institutions.
- **`programs`**: The actual "product" a student enrolls in.
  - *Connection*: Belongs to a **Branch** and is owned by an **Institution** or an **Instructor** Profile.
- **`courses`**: A program is made up of multiple courses.
  - *Connection*: Belongs to exactly **one** Program.
- **`course_modules`**: The chapters or sections inside a course.
  - *Connection*: Belongs to exactly **one** Course.
- **`lessons`**: The actual granular learning materials (videos, articles, quizzes).
  - *Connection*: Belongs to a **Course**, and optionally sits inside a **Module**.

### 2.1. The Community Layer (Inside Programs)
To foster engagement and interaction, each `program` acts as a container for community features, transforming a static course into a dynamic learning environment.

- **Discussion Forum (`program_posts`)**: This table facilitates discussions within a program.
  - *Connection*: Each post belongs to one **Program** and is written by one **Profile** (the author).
  - *Features*: Supports threaded conversations via a self-referencing `parent_post_id` for replies.

- **Instructor Announcements (`program_announcements`)**: A way for program owners (teachers/institutions) to broadcast updates.
  - *Connection*: Each announcement belongs to one **Program** and is written by the instructor **Profile**.

- **Member List**: This is not a separate table. A list of all students in a program can be generated by querying the **`enrollments`** table for a given `program_id`.
  - *Connection*: Shows all **Profiles** that have an active **Enrollment** in the program.

### 3. The People & Organizations (The "Who")
- **`profiles`**: Every user on the platform (Students, Teachers, Admins). Holds name, avatar, and roles.
- **`institutions`**: Schools, universities, or training centers.
- **`institution_memberships`**: The bridge between Profiles and Institutions. Links a `profile` to an `institution` with a specific role (e.g., "staff" or "instructor").

### 4. Student Engagement (The Action)
How students interact with the catalog and learning paths.
- **`enrollments`**: When a student joins a program. Links one **Profile** to one **Program**. Tracks overall completion.
- **`lesson_progress`**: Tracks exactly where a student is. Links one **Profile** to one **Lesson**.
- **`inquiries` & `contact_messages`**: Questions from students. Inquiries link to a **Branch**, while contact messages are general support.
- **`reviews` & `bookmarks`**: Star ratings or saved items. Students can review/bookmark both **Branches** (theoretical fields) and **Programs** (actual course offerings).

### Summary Flow
**Major** → has many → **Branches** → has many → **Programs** → has many → **Courses** → has many → **Modules** → has many → **Lessons**.  
A **Student** creates an **Enrollment** in a **Program**, which allows them to generate **Lesson Progress** on the **Lessons**.

## Top-Level Routes
The app lives under a language prefix: `/fr` or `/ar`.

### Main public pages
- `/fr` or `/ar`
  - Home page with hero, branch search, featured programs, and top benefits.
- `/fr/login` or `/ar/login`
  - Login page. Uses `AuthForm` to authenticate via Supabase.
- `/fr/signup` or `/ar/signup`

- `/fr/majors/[majorSlug]/[branchSlug]` or `/ar/majors/[majorSlug]/[branchSlug]`

- `/fr/for-students` or `/ar/for-students`
  - Benefits page for prospective students.
- `/fr/for-teachers` or `/ar/for-teachers`
  - Benefits page for prospective teachers.
- `/fr/for-institutions` or `/ar/for-institutions`
  - Benefits page for prospective institutions.

- `/fr/institutions` or `/ar/institutions`
  - Institution catalog page.
- `/fr/institutions/[slug]` or `/ar/institutions/[slug]`
  - Single institution detail page.
- `/fr/blog` or `/ar/blog`
  - Blog listing page.

  - Blog post detail page.
- `/fr/events` or `/ar/events`

## Key features by page
### Public catalog
- `Home` - branch search, hero, featured benefits
- `Majors` - browse major categories, then branch lists
- `Branch details` - branch overview, gallery, FAQs, inquiry form
- `Institutions` - browse institutions and read institution details
- `Blog` - list blog posts and view individual article details
- `Events` - list upcoming/ongoing events and event registration
- `FAQ` - category-based FAQ accordion
- `Programs` - list programs and branch links

### Authentication
- Login and signup pages are built with `AuthForm`.
- Signup sends a Supabase signup request with redirect callback.
- Login pushes users to `/student` after successful auth.

### Admin management
- Admin dashboard cards show counts of majors, institutions, programs, events, blog posts, inquiries, reviews, and FAQ entries.
- Admin areas are wrapped by `AdminDashboardLayout`.
- Each admin section is a managed CRUD list where items can be created or edited.

### Student dashboard
- Student pages are wrapped by `StudentDashboardLayout`.
- Bookmarks page fetches favorites for the signed-in user.
- Pages appear to be placeholders for a student experience flow.

### Institution dashboard
- Wrapped by `InstitutionDashboardLayout`.
- Allows institution admins to manage their specific programs and invite teachers.

### Teacher dashboard
- Wrapped by `TeacherDashboardLayout`.
- Allows teachers to view their programs and create new ones.

## Notes on structure
- All pages are organized under `src/app/[lang]`.
- The app uses route-group folders like `(catalog)` and `(dashboard)` to group pages without affecting final URLs.
- Auth pages are in `(auth)` and use a lightweight centered layout.
- Admin/student dashboards use sidebar layouts and custom wrappers.

---

## Helpful hints
- Search for `href={`${lang}/...`}` in pages to trace navigation behavior.
- Look at `src/components/ui/DashboardLayout.tsx` for how dashboard sidebars and logout work.
- The public navbar is in `src/components/ui/Navbar.tsx` and hides itself on admin/student routes.
- Language handling and types are centralized in `src/lib/i18n.ts` and `src/lib/dictionary.ts`.
- Supabase clients (browser and server) are cleanly centralized in `src/lib/supabase/`.
